# Requirements Document

## Introduction

This feature implements a comprehensive user profile and resume management system for the AutoApply Chrome extension. It includes a multi-step onboarding wizard that collects professional information, a structured resume data model, PDF upload to Supabase Storage, an experience/skills bank with full CRUD, and resume version history. Downstream features (auto-fill, ATS optimization) depend on this structured data.

## Glossary

- **Onboarding_Wizard**: The multi-step UI flow that collects a user's professional profile for the first time.
- **Profile**: The persisted record in `public.profiles` containing personal, educational, and professional metadata for a user.
- **Experience**: A single work, project, volunteer, or education entry stored in the `experiences` table.
- **Skill**: A named competency with category and proficiency level stored in the `skills` table.
- **Resume**: A record in the `resumes` table representing either a base PDF upload or a tailored version generated by the ATS optimizer.
- **StructuredResume**: A JSON representation of a resume composed of personal info, summary, experience[], education[], skills[], and projects[].
- **Experience_Bank**: The collection of all Experience records for a user, supporting CRUD operations.
- **Skills_Bank**: The collection of all Skill records for a user, supporting CRUD operations.
- **Profile_Store**: The Zustand store managing profile, experience, skills, and resume state in the side panel.
- **Profile_Page**: The post-onboarding UI page where users view and edit their profile data.
- **Resume_Upload**: The process of uploading a PDF file to Supabase Storage under the authenticated user's folder.

## Requirements

### Requirement 1: Database Schema

**User Story:** As a developer, I want the database schema to capture all professional profile data, so that the extension can store and retrieve structured user information.

#### Acceptance Criteria

1. THE Database SHALL extend the `profiles` table with columns: `phone`, `location`, `linkedin_url`, `portfolio_url`, `github_url`, `university`, `degree`, `graduation_year`, `field_of_study`, `years_of_experience`, `headline`, `summary`.
2. THE Database SHALL contain an `experiences` table with columns: `id` (UUID PK), `user_id` (UUID FK → auth.users), `type` (TEXT: work/project/volunteer/education), `title` (TEXT), `organization` (TEXT), `location` (TEXT), `start_date` (TEXT), `end_date` (TEXT), `is_current` (BOOLEAN), `bullets` (JSONB), `skills` (JSONB), `sort_order` (INTEGER).
3. THE Database SHALL contain a `skills` table with columns: `id` (UUID PK), `user_id` (UUID FK → auth.users), `name` (TEXT), `category` (TEXT), `proficiency` (TEXT), and a UNIQUE constraint on `(user_id, name)`.
4. THE Database SHALL contain a `resumes` table with columns: `id` (UUID PK), `user_id` (UUID FK → auth.users), `title` (TEXT), `type` (TEXT: base/tailored), `content` (JSONB), `file_path` (TEXT), `file_size` (INTEGER), `application_id` (UUID nullable), `ats_score` (INTEGER nullable), `is_primary` (BOOLEAN DEFAULT false), `metadata` (JSONB), `created_at` (TIMESTAMPTZ), `updated_at` (TIMESTAMPTZ).
5. THE Database SHALL enforce Row Level Security on `experiences`, `skills`, and `resumes` tables scoped to `auth.uid()`.
6. THE Database SHALL contain a Supabase Storage bucket named `resumes` with RLS policies restricting each user to read and write only within their own `{user_id}/` path prefix.

### Requirement 2: TypeScript Types

**User Story:** As a developer, I want strongly-typed interfaces for all profile data structures, so that the codebase has compile-time safety across profile, experience, skill, and resume operations.

#### Acceptance Criteria

1. THE Codebase SHALL define an `Experience` interface with fields matching the `experiences` table schema.
2. THE Codebase SHALL define a `Skill` interface with fields matching the `skills` table schema.
3. THE Codebase SHALL define a `Resume` interface with fields matching the `resumes` table schema.
4. THE Codebase SHALL define a `StructuredResume` interface with fields: `personal` (object), `summary` (string), `experience` (Experience[]), `education` (Experience[]), `skills` (Skill[]), `projects` (Experience[]).
5. THE Codebase SHALL define a `ProfileData` interface extending `UserProfile` with all additional profile columns added in Requirement 1.

---

### Requirement 3: Profile Data Access Layer

**User Story:** As a developer, I want a data access module for profile operations, so that UI components can read and write profile data through a consistent API.

#### Acceptance Criteria

1. THE Profile_Library SHALL expose a `fetchProfile(userId)` function that returns the full `ProfileData` for the given user.
2. THE Profile_Library SHALL expose an `updateProfile(userId, data)` function that persists partial profile updates to Supabase.
3. THE Profile_Library SHALL expose `fetchExperiences(userId)`, `createExperience(data)`, `updateExperience(id, data)`, and `deleteExperience(id)` functions for Experience CRUD.
4. THE Profile_Library SHALL expose `fetchSkills(userId)`, `upsertSkill(data)`, and `deleteSkill(id)` functions for Skills CRUD.
5. THE Profile_Library SHALL expose an `uploadResume(userId, file, onProgress)` function that uploads a PDF to Supabase Storage at path `{userId}/{timestamp}_{filename}` and returns the storage path.
6. THE Profile_Library SHALL expose `fetchResumes(userId)` and `createResumeRecord(data)` functions for resume metadata CRUD.
7. WHEN a Supabase operation fails, THE Profile_Library SHALL return a typed error object rather than throwing an unhandled exception.

---

### Requirement 4: Profile Zustand Store

**User Story:** As a developer, I want a Zustand store for profile state, so that all side panel components share a single source of truth for profile, experience, skills, and resume data.

#### Acceptance Criteria

1. THE Profile_Store SHALL hold state for: `profile` (ProfileData | null), `experiences` (Experience[]), `skills` (Skill[]), `resumes` (Resume[]), `isLoading` (boolean), `error` (string | null).
2. THE Profile_Store SHALL expose actions: `loadProfile`, `saveProfile`, `loadExperiences`, `addExperience`, `editExperience`, `removeExperience`, `loadSkills`, `addSkill`, `removeSkill`, `loadResumes`.
3. WHEN `loadProfile` is called, THE Profile_Store SHALL fetch profile data and update state atomically.
4. WHEN an action fails, THE Profile_Store SHALL set the `error` field with a descriptive message and set `isLoading` to false.

### Requirement 5: Onboarding Wizard

**User Story:** As a job seeker, I can fill out my professional profile once through a guided wizard, so that the extension has all the data it needs to auto-fill applications.

#### Acceptance Criteria

1. THE Onboarding_Wizard SHALL present steps in order: Personal Info → Education → Experience → Skills → Resume Upload → Review.
2. THE Onboarding_Wizard SHALL display a step indicator showing the current step number and total steps.
3. WHEN the user completes the Review step and confirms, THE Onboarding_Wizard SHALL set `onboarding_completed = true` on the user's profile record.
4. WHEN `onboarding_completed` is set to true, THE Onboarding_Wizard SHALL update the `useAuthStore` user object to reflect the new value.
5. THE Onboarding_Wizard SHALL allow the user to navigate back to previous steps without losing entered data.
6. WHEN the user is on a step other than the first, THE Onboarding_Wizard SHALL display a "Back" button.
7. THE Personal_Info_Step SHALL collect: full name, email (pre-filled, read-only), phone, location, LinkedIn URL, portfolio URL, GitHub URL, headline.
8. THE Education_Step SHALL collect: university, degree, field of study, graduation year.
9. THE Experience_Step SHALL allow adding multiple work experience entries, each with: title, organization, location, start date, end date, is-current toggle, and bullet points.
10. THE Skills_Step SHALL allow adding skills with name, category, and proficiency level (beginner/intermediate/advanced/expert).
11. THE Resume_Upload_Step SHALL accept PDF files up to 10 MB via drag-and-drop or file picker, and SHALL display upload progress as a percentage.
12. IF a non-PDF file is selected, THEN THE Resume_Upload_Step SHALL display an error message "Only PDF files are supported".
13. IF a file exceeding 10 MB is selected, THEN THE Resume_Upload_Step SHALL display an error message "File must be under 10 MB".
14. THE Review_Step SHALL display a read-only summary of all entered data grouped by section.

---

### Requirement 6: Profile Page (Post-Onboarding Editor)

**User Story:** As a job seeker, I can edit my profile after completing onboarding, so that I can keep my information current.

#### Acceptance Criteria

1. THE Profile_Page SHALL display all profile sections: Personal Info, Education, Experience Bank, Skills Bank, and Resumes.
2. THE Profile_Page SHALL allow inline editing of personal info and education fields with a save action.
3. THE Profile_Page SHALL allow adding, editing, and deleting entries in the Experience Bank.
4. THE Profile_Page SHALL allow adding and deleting entries in the Skills Bank.
5. THE Profile_Page SHALL display a list of uploaded resumes with title, type, upload date, and a download link.
6. WHEN a profile save succeeds, THE Profile_Page SHALL display a success confirmation to the user.
7. WHEN a profile save fails, THE Profile_Page SHALL display the error message returned by the Profile_Library.

---

### Requirement 7: App Routing Integration

**User Story:** As a job seeker, I am automatically directed to the onboarding wizard on first login, so that I am guided through profile setup before accessing the main app.

#### Acceptance Criteria

1. WHEN the authenticated user's `onboarding_completed` is false, THE App SHALL navigate to `/onboarding`.
2. WHEN the authenticated user's `onboarding_completed` is true, THE App SHALL navigate to `/` (dashboard).
3. THE App SHALL render the `OnboardingWizard` component at the `/onboarding` route.
4. THE App SHALL render the `ProfilePage` component at the `/profile` route.
5. WHEN an unauthenticated user attempts to access `/onboarding` or `/profile`, THE AuthGuard SHALL redirect the user to the login screen.
